# Learned notes

A dispatch system on [`headroom`](../headroom/README.md), replacing only its `NoteReader` with
`LearnedNoteReader`. The rule reader in [`strategies/notes`](../notes/README.md) stays unchanged. Admission, pricing,
fees, offers and bundling are headroom's.

| File          | What it holds                                                                 |
| ------------- | ----------------------------------------------------------------------------- |
| `reader.py`   | `LearnedNoteReader`: base rules first, then additional facts from JSON        |
| `phrases.json`| Reviewed literal phrases and regular expressions, generated by `fit.py`        |
| `fit.py`      | Offline candidate extraction from reveal JSON in committed saved weeks        |
| `dispatch.py` | The headroom desk with this reader and the `learned-notes` recording policy   |

## Regenerate the data offline

From the repository root:

```sh
uv run python -m strategies.learned_notes.fit
```

This reads only existing `data/scrape/runs/**/reveal.json.gz` files and replaces
`strategies/learned_notes/phrases.json`. It makes no network requests and needs no database. Use `--runs` and `--out`
to select another local input or output path.

The fitter keeps won cars' first legs, where note truth is revealed. When the base reader returns `NO_FACTS` and the
reveal differs from the request's stated pickup, hours, deadline or car facts, it proposes the whole normalised note
as a literal, with the differing facts and a `support` count. Repeated literals with conflicting facts are omitted.
When no usable reveals exist it writes an empty `phrases.json` and says so. Candidates remain suggestions: inspect
and edit them before use, and review the regenerated diff rather than accepting every proposal automatically.

## Data and merging

Each entry has exactly one selector:

```json
{
  "phrases": [
    {
      "literal": "a note paraphrase",
      "regex": null,
      "facts": {
        "ready_at": {"days": 1, "minute": 720},
        "pickup_hours": {"opens": 540, "closes": 900},
        "manual": true
      },
      "support": 3
    }
  ]
}
```

In real entries, omit the selector that is not used; the `null` above only illustrates both names. `regex` is a
regular expression evaluated case-insensitively against the normalised note; a literal is normalised and matched as
a substring. Times are relative to the request's arrival day (`days` plus `minute` from midnight), hours use the
same minutes, and `released_at`, `deadline`, `delivery_hours`, `plates` and `summer_tyres` use the corresponding
base `NoteFacts` fields. `support` is review metadata and does not affect reading.

For every request, the base `NoteReader` runs first. Matching learned phrases then run in file order, but **only
missing facts are filled**. Base values always win; learned values cannot shorten or move a time, replace hours, or
switch a car fact off. Partial `Hours` merge field by field. When several learned phrases supply the same missing
fact, the earliest one wins.

This is reviewed data, not an ML model: fitting extracts explicit phrases and reveal facts, and no training or
inference service is involved. With an empty `phrases.json`, the reader returns exactly the base reader's facts.

## Run it

From the repository root:

```sh
uv run strategies/learned_notes/dispatch.py --level 8 --seed spread-1
```
